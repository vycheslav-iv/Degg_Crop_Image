## 0. Статус: рефакторинг редактора СДЕЛАН

Редактор переписан по-честному (архитектура — SPEC §5.0.1), все проверки
зелёные, шесть мутаций дали красный детектор. Чекпоинт-коммит `edfa0c0` остался
точкой отката.

Что изменилось:
- **Два источника истины**: `state.frac` (геометрия кадра, в `crop_rect`) и
  `state.manual` (ручной размер результата, в `output_size`). Всё остальное —
  производные функции (`cropPx`, `cropRatio`, `resultSize`, `effectiveRatio`),
  ничего лишнего не хранится.
- **Ровно две точки записи в виджет**: `writeWidget(widget, value, { call })`
  (call:false — тихая, call:true — как фронтенд) и `programmatic()` (запись с
  callback'ом под защитой `state.suppress`). Ушли `setWidgetValue`,
  `setWidgetValueQuiet`, прямые `widget.value = …` в логике.
- **Одна точка применения состояния**: `commit()` = persist + syncViews +
  refreshLayoutSize + layout. Все операции идут через неё.
- **Явные операции с политиками**: `moveOrResizeCrop`, `applyRatioPreset`,
  `setResultSize`, `setMegaPixels`, `setFrameCenter`, `resetCrop`,
  `loadStateFromWidgets`, `dropStaleManual`.
- **`layout()` стала чистой** — только читает состояние и рисует; побочных
  эффектов (сверки, сброса ручного режима) в отрисовке больше нет.
- **Именованные константы**: `MAX_FRAC`, `RATIO_TOLERANCE`, `MEGAPIXEL_UNIT`,
  `MIN_CROP_PX`, `MIN_RATIO_PX` (были магические 100 / 0.005 / 1024² / 16 / 8).
- **Новые чистые функции** (покрыты смоуком): `parseManualSize`, `fracRatio`,
  `ratiosMatch`.
- **Тестовых хуков в редакторе нет**: наружу `widget`, `refresh`, `layout`,
  `commit`, `state`. Проба задаёт кадр через `crop_rect` + `refresh()` — так же,
  как это делает воркфлоу.
- **Проба на настоящей неквадратной картинке** (`image_flux3_klein...png`,
  2720×1536) вместо подмены `state.img`; если файла нет — проверка пропускается с
  предупреждением; ожидаемый размер считает PYTHON (`ci.output_size`).

## 1. Что делали в этой сессии (кратко)
- «Зафиксировано» фиксирует ТЕКУЩИЕ пропорции рамки; выбор пресета применяет его
  и включает замок; «Свободные» снимают.
- Shift-приёмы: перенос строго по одной оси, ресайз края с сохранением пропорций.
- Координаты центра рамки — нативные опции `center_x`/`center_y` под «Фиксацией
  пропорций».
- РАЗМЕР РЕЗУЛЬТАТА — нативные опции `frame_w`/`frame_h` (ИТОГОВЫЙ размер
  картинки — те же числа, что в плашке и в выходах width/height): вбил
  1000 × 1000 → в плашке 1000 × 1000; кратность учитывается; остальные параметры
  подстраиваются; обратное направление — выбор пресета или правка MP возвращают
  режим «по мегапикселям».
- Кнопка «?» — в правом верхнем углу ПРЕВЬЮ; подсказка в корне.
- Разгон рамки при drag починен (снимок `state.drag.view` на pointerdown).

## 3. Проблемы, которые встречались (и как решали)
- ⛔ ГЛАВНЫЙ БАГ (поймал пользователь на воркфлоу «Test Crop»): JS считал
  пропорции результата по ДОЛЯМ кадра, Python — по ПИКСЕЛЯМ. На неквадратном
  источнике это разные пропорции (рамка 1731×974 px = 16:9 в долях 0.636×0.634)
  → UI показывал 1448 × 1448 вместо 1928 × 1088. Исправлено: `resultSize()`
  берёт `cropPx()`.
  ⚠️ ПОЧЕМУ ПРОПУСТИЛ: живая проба работала на `example.png` 768×768 (квадрат) —
  доли и пиксели совпадают. Теперь есть регресс на настоящей неквадратной
  картинке и `tests/_check_real_workflow.py` на реальном воркфлоу.
- Ручной размер перебивал пресет и MP (устаревшее значение из прошлого воркфлоу)
  → `dropStaleManual()` (сверка пропорций) при загрузке и при смене картинки.
- Свободный drag и сверка конфликтовали → ручной размер подстраивается В
  операции `moveOrResizeCrop` (до изменения кадра).
- Разгон рамки при drag (доля 88, пропорции 1:1) → фиксация `state.drag.view`.
- Слабые детекторы (найдены мутациями) → ужесточены до конкретных форм.
- Ожидания в живой пробе были «зашиты» (1448 × 1448, 16:9) — переписаны на
  расчёт от фактических пропорций кадра через Python (`ci.output_size`), иначе
  проверка врала при других пропорциях.
- ⚠️ Потеря реализации: `cp` старого бэкапа поверх свежего файла откатил всю
  переработку → восстановлено из рабочей копии ComfyUI. Правило: бэкапы только
  из `git`; перед крупной переработкой — коммит-чекпоинт.
- Сервер не подхватил новые входы: ComfyUI запущен ДО `sync.py` → стоп → sync →
  старт.

## 4. Что важно не сломать при продолжении работе
- ⛔ Итоговый размер — по ПИКСЕЛЯМ кадра (`cropPx()`), как в Python. Доли ≠
  пиксели на неквадратном источнике.
- ⛔ Живая проба обязана покрывать неквадратный источник (квадратный скрывает
  баг); ожидания — от фактических пропорций, а не «зашитые» числа.
- `frame_w`/`frame_h` = ИТОГОВЫЙ размер результата, НЕ размер обреза.
- ⛔ ИНВАРИАНТ пропорций: кадр ↔ ручной результат; сверка — `dropStaleManual()`
  (при загрузке и при смене картинки), НЕ в `layout()`.
- Ручной режим: MP = эквивалент (информационно), правка MP = возврат в режим MP;
  выбор пресета = сброс ручного режима; свободный drag = адаптация ручного
  размера (ширина сохраняется).
- Ручной размер ТОЧНО живёт в скрытом `output_size`; через MP его гонять нельзя.
- Любое изменение состояния — через операцию → `commit()`. Правка виджета
  напрямую (в обход операции) ломает синхронизацию.
- Координаты/размер — ТОЛЬКО нативные виджеты под «Фиксацией пропорций».
- Запись в виджет — тихая; громкая только через `programmatic()`.
- DRAG-ИНВАРИАНТ: `state.drag.view` нельзя убирать.
- «Сбросить» НЕ применяет пропорции и НЕ меняет настройки результата.
- Значения COMBO — протокол; переводы только через `getOptionLabel`.
- `sync.py` после правок; Python-правка = рестарт ComfyUI, JS — `Ctrl+Shift+R`.
- Запрещены: `setInterval`/`MutationObserver`/`visibilitychange`, глобальные
  `window`-слушатели, `options.disabled`, `scripts/app.js`, canvas-рисование.
