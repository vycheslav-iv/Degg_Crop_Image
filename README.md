# Degg Crop Image

**Degg Crop Image** — нода кадрирования с интерактивной рамкой прямо на теле ноды (как Crop Tool в Capture One). Рамку можно тянуть за края и углы, она **выходит за пределы изображения** — это даёт outpainting без второго входа.

Категория: `My_custom_nodes/Image` · имя ноды: `Degg Crop Image`.

Превью источника появляется **сразу по проводу** (как в нативной ноде кадрирования): воркфлоу запускать не нужно.

---

# Возможности

- Рамка в **долях** изображения — зум графа и размер ноды на результат не влияют
- 8 маркеров (углы + стороны) и перетаскивание всей рамки
- `Затемнение вне рамки` 0–100 % — **только отображение** (в PNG не попадает)
- Плашка `W × H px   N.NN MP` — живой расчёт итогового размера, одна строка (MP фактические, как в ядре)
- Пропорции: `Свободные, 1:1, 2:3, 3:2, 4:3, 3:4, 16:9, 9:16, 21:9` + `Фиксация пропорций` (вкл. по умолчанию). Смена пропорции сохраняет центр и площадь рамки
- `Зафиксировано` фиксирует **текущие** пропорции рамки (не пресет из списка); выбор пресета в списке применяет его и включает фиксацию, выбор `Свободные` — снимает
- Координаты центра рамки — обычные опции ноды `Центр рамки X` / `Центр рамки Y` (под «Фиксацией пропорций», как остальные бегунки): **в пикселях оригинала** относительно центра изображения; ввод двигает рамку
- Размер результата — опции `Ширина результата, px` / `Высота результата, px`: задают **итоговый размер картинки** (те же числа, что в плашке и в выходах `width`/`height`). Ввёли 1000 × 1000 → в плашке 1000 × 1000, кратность учитывается (1333 → 1336 при кратности 8)
- Остальные параметры подстраиваются под ручной размер: пропорции кадра приводятся к пропорциям результата (площадь и центр сохраняются, кадр не растянется), а мегапиксели показывают эквивалент результата
- Обратное направление: выбор пресета пропорций или правка мегапикселей возвращают обычный режим, и поля снова показывают размер, посчитанный от мегапикселей (16:9 + 2 МП → 1928 × 1088)
- Размер результата считается по пикселям кадра, а не по его долям: на неквадратном источнике (16:9) рамка 0.636×0.634 в долях даёт 1928 × 1088, а не 1448 × 1448
- Ручной размер никогда не перебивает пропорции и мегапиксели: если они разошлись (например, ручной размер остался от прошлого воркфлоу) — ручной режим сбрасывается, иначе кадр растянулся бы
- Shift-модификаторы в режиме `Свободные`: Shift + перетаскивание = строго по одной оси, Shift + край/угол = ресайз с сохранением текущих пропорций (фиксацию при этом не включает)
- Кнопки «вписать рамку в изображение» и «центрировать»
- **Подключение или смена картинки сбрасывает ноду под неё**: рамка — по всему
  изображению, центр = 0, пропорции = пропорции картинки (фиксация на них), а
  размер результата = размер картинки в пикселях. Кнопка «Сбросить» делает
  ровно то же. При этом **открытие сохранённого воркфлоу рамку не трогает** —
  там кадр берётся из воркфлоя
- ⛔ Смена картинки **затирает мегапиксели**: после сброса в поле «Мегапиксели» стоит площадь картинки (следствие «значения = значения изображения»). Чтобы вернуть нужное разрешение, впишите мегапиксели заново
- Иконка «?» в правом верхнем углу превью — подсказка по всем приёмам (Shift, координаты, замок)
- Кратность `8…128` шагом `4` (как в «Выборе разрешения»): каждая сторона округляется независимо до ближайшей кратности
- Выходы: `IMAGE`, `MASK`, `width`, `height` — **фактические** размеры результата
- Вход `mask` (необязательный) заменяет альфу источника
- Заливка — **фон аутпейнта**: слой под изображением, поэтому внутри кадра картинку не перекрывает, а за её границей даёт цвет (`transparent / black / white / gray`)
- Batch: рамка общая, один выходной размер на всю партию — размер считается от **первого** кадра партии (у кадров разного размера результат один)
- Локализация RU / EN
- Рамка сохраняется в workflow (скрытый вход `crop_rect`)

# Входы

| Имя | Тип | По умолчанию | Назначение |
|-----|-----|--------------|------------|
| `image` | IMAGE | — | Источник (батч) |
| `aspect_ratio` | combo | `free` | Пропорция рамки |
| `lock_ratio` | BOOLEAN | `true` | `Зафиксировано` / `Свободные`: держать текущие пропорции рамки при перетаскивании |
| `center_x` | INT | `0` | Смещение центра рамки по горизонтали от центра изображения, px (знак любой) |
| `center_y` | INT | `0` | Смещение центра рамки по вертикали от центра изображения, px (знак любой) |
| `frame_w` | INT | `0` | Итоговая ширина результата, px |
| `frame_h` | INT | `0` | Итоговая высота результата, px |
| `dim_outside` | INT 0…100 | `50` | Затемнение вне рамки (только вид) |
| `multiplicity` | INT 8…128 шаг 4 | `8` | Кратность итоговых сторон |
| `megapixels` | FLOAT 0.1…64 | `2.0` | Целевая площадь выхода, 1 MP = 1024 × 1024 px |
| `resample` | combo | `lanczos` | `lanczos / bicubic / bilinear / nearest-exact` (значения не переводятся, как в стандартных нодах) |
| `fill` | combo | `transparent` | Фон вне источника (слой под изображением) |
| `mask` | MASK (опц.) | — | Альфа источника (1 = непрозрачно) |
| `crop_rect` | STRING (скрыт) | полный кадр | Рамка: `{x, y, w, h}` в долях |

# Выходы

| Имя | Тип | Что |
|-----|-----|-----|
| `image` | IMAGE | Кадр (или расширенный холст) |
| `mask` | MASK | Альфа результата; при `transparent` залитая область = 0 |
| `width` | INT | Фактическая ширина |
| `height` | INT | Фактическая высота |

> Значения combo — **протокол**: подписи меняются через `getOptionLabel`, сами значения (`16:9`, `lanczos`, …) в workflow не переводятся.

# Как считается размер

`megapixels` — **целевая** площадь результата, а не размер выделенной области (ТЗ §7.2): рамка задаёт только пропорцию и содержимое, поэтому маленький кадр увеличивается, а большой — уменьшается.

Формула полностью повторяет ядро ComfyUI (`comfy_extras/nodes_resolution.py`, нода «Выбор разрешения»), поэтому одинаковые пропорция/MP/кратность дают одинаковые числа в обеих нодах:

1. `1 MP = 1024 × 1024 px`, `scale = sqrt(MP × 1024² / (Rw × Rh))`, где `Rw : Rh` — отношение сторон рамки (в свободном режиме — текущее).
2. `W = round(Rw × scale / multiplicity) × multiplicity`, `H` — так же независимо. Банковское округление, как в Python.
3. Границы источника при дробной рамке раскрываются наружу (`floor` / `ceil`), поэтому кадр не теряет пиксели.

Примеры (`MP` / кратность → результат):

```
1000 × 1000, 2.0 MP, 8  →  1448 × 1448
1920 × 1080, 2.0 MP, 8  →  1928 × 1088
1600 ×  900, 1.0 MP, 64 →  1344 ×  768
 850 × 1000, 1.0 MP, 10 →   940 × 1110
```

Плашка под рамкой показывает **фактические** `W × H` и фактические МП **одной строкой через отступ** (`1928 × 1088 px   2.10 MP`; 2.10 вместо заказанных 2.0 — так же округляет и ядро).
