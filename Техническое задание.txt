# Техническое задание: кастомная нода ComfyUI «Degg Crop Image»

## 1. Назначение

Разработать кастомную ноду для ComfyUI с названием **Degg Crop Image**.

Нода предназначена для интерактивного кадрирования изображений по принципу Crop Tool в Capture One, с возможностью расширять границы кадра за пределы исходного изображения для подготовки изображения к outpainting.

Нода должна объединять:
- Интерактивное кадрирование изображения мышью.
- Свободное перемещение и изменение размера рамки.
- Фиксированные и свободные пропорции кадра.
- Расчёт выходного разрешения по заданным параметрам.
- Настройку кратности разрешения и количества мегапикселей.
- Выбор метода масштабирования.
- Создание полей за пределами исходного изображения.
- Прозрачную или цветную заливку добавленных областей.
- Вывод итогового изображения, его ширины и высоты.

**Главный принцип:** пользователь должен управлять кадрированием непосредственно на превью изображения внутри ноды, без необходимости вводить координаты вручную.

## 2. Совместимость и архитектура

1. Разрабатывать ноду для интерфейса ComfyUI Nodes 2.0 и последующих совместимых версий.
2. Использовать актуальный механизм расширения frontend, предусмотренный установленной версией ComfyUI.
3. Не строить реализацию исключительно на устаревших API LiteGraph, если для соответствующей версии Nodes 2.0 существует актуальный способ реализации.
4. Python-часть должна выполнять обработку изображений, а frontend-часть — отображать интерактивное превью и обрабатывать действия мышью.
5. Не использовать сторонние зависимости, если аналогичная функциональность доступна средствами ComfyUI, браузера или Pillow/PyTorch.
6. Не изменять исходный код ComfyUI.
7. Все файлы ноды должны находиться в отдельной папке `custom_nodes`, а frontend-ресурсы — внутри папки этой ноды.
8. Сохранять совместимость с обычными IMAGE-выходами и входами других нод ComfyUI.

До начала разработки агент должен изучить API установленной версии ComfyUI, механизм создания frontend-расширений для Nodes 2.0 и реализацию штатных нод:
- «Создать ограничивающие рамки» — как образец отображения изображения и работы с рамками.
- «Выбор разрешения» — как образец принципа настройки кратности и разрешения.

Названия приведены для поиска соответствующих нод в установленной версии. Не считать их внутренние API гарантированно доступными для прямого повторного использования.

Если отдельная возможность ещё не поддерживается официальным API Nodes 2.0, необходимо выбрать совместимый способ реализации и документировать его. Не подменять интерактивное кадрирование обычными числовыми полями.

## 3. Вход ноды

Один обязательный вход:

- `изображение` — IMAGE.

При подключении изображения оно автоматически отображается в области превью ноды.

Поддерживать стандартный формат IMAGE ComfyUI: тензор изображения с размерами `[B, H, W, C]`.

Для батчей:
- Все изображения в батче должны обрабатываться одинаковыми параметрами кадрирования.
- Если размеры изображений различаются, координаты рамки должны интерпретироваться в нормализованной системе координат, чтобы сохранялось одинаковое расположение кадра относительно каждого изображения.
- Итоговые ширина и высота должны соответствовать общим выходным размерам обработанных изображений.

Предусмотреть корректную обработку изображений с альфа-каналом, если он присутствует.

## 4. Интерактивное превью и рамка кадрирования

### 4.1. Общий вид

Внутри ноды отображается исходное изображение с прямоугольной рамкой кадрирования поверх него.

Превью должно работать по принципу инструмента Crop в Capture One:
- изображение отображается целиком или в масштабе, позволяющем редактировать рамку;
- рамка имеет заметную границу;
- внутри рамки изображение отображается без затемнения;
- область за пределами рамки затемняется;
- рамка может перемещаться и менять размер;
- границы рамки могут выходить за пределы исходного изображения.

Превью должно автоматически подстраиваться под доступную ширину ноды. При необходимости высота превью увеличивается, но не должна бесконтрольно занимать всё рабочее пространство. При изменении размера ноды превью пересчитывает масштаб отображения без изменения реальных координат кадрирования.

### 4.2. Как должна работать рамка

Рамка представляет собой прямоугольную область будущего изображения.

У рамки должны быть:
- четыре угловые точки изменения размера;
- четыре точки изменения размера на серединах сторон;
- возможность перемещения всей рамки;
- визуально различимая граница;
- удобные для захвата мышью области, даже если сами маркеры небольшие.

Поведение мыши:

**Перемещение рамки**
- При нажатии левой кнопкой мыши внутри рамки и перетаскивании рамка перемещается относительно исходного изображения.
- Размер рамки при этом не меняется.
- Перемещение не должно ограничиваться исходными границами изображения.
- Пользователь может переместить рамку влево, вправо, вверх или вниз, включая области полностью или частично за пределами исходника.

**Изменение размера**
- При перетаскивании углового маркера изменяются ширина и высота рамки.
- При перетаскивании маркера стороны изменяется соответствующая ширина или высота.
- При включённой фиксации пропорций изменение одного измерения должно автоматически корректировать второе.
- При выключенной фиксации ширина и высота регулируются независимо.
- Изменение размера рамки не должно приводить к её автоматическому прилипанию к краям исходного изображения.
- Рамка не может иметь нулевую или отрицательную ширину либо высоту. Предусмотреть минимальный допустимый размер.

**Выход за границы исходника**
- Рамка может выходить за любую из четырёх границ изображения.
- Допускается выход сразу за несколько границ.
- Вся площадь рамки, выходящая за исходное изображение, считается новой областью, которую необходимо заполнить выбранным цветом или прозрачностью.
- Превью должно визуально показывать и исходное изображение, и внешнюю область рамки.

### 4.3. Уменьшение превью для outpainting

Когда рамка расширяется за пределы исходника, превью должно автоматически уменьшать масштаб отображения изображения и рамки, если это необходимо для показа всей области кадрирования.

Например, если исходное изображение имеет размер 1024 × 1024, а пользователь расширяет рамку до области 1536 × 1024, превью должно уменьшить отображение так, чтобы были видны и исходник, и добавленные поля.

Алгоритм отображения:
1. Рассчитать прямоугольник, включающий исходное изображение и текущую рамку.
2. Определить масштаб, при котором весь этот прямоугольник помещается в доступную область превью.
3. Отобразить исходное изображение с этим масштабом.
4. Отобразить рамку в тех же экранных координатах.
5. Пересчитывать масштаб при перемещении рамки за пределы изображения, изменении её размера и изменении размеров ноды.

Уменьшение превью не должно менять реальные координаты рамки и размеры итогового изображения.

Важно: при изменении масштаба рамка должна оставаться на том же месте относительно исходного изображения. Нельзя привязывать её координаты только к пикселям экрана.

### 4.4. Затемнение за пределами рамки

Вся область превью за пределами рамки затемняется.

Добавить параметр:

- `Затемнение вне рамки` — 0–100%, по умолчанию 50%.

Правила:
- 0% — затемнения нет.
- 100% — область за рамкой максимально затемнена.
- Промежуточные значения изменяют интенсивность затемнения.
- Затемнение применяется только к отображению превью, а не к выходному изображению.
- Если рамка выходит за пределы исходника, внешняя область должна визуально отличаться от исходного изображения и оставаться различимой.

Значение затемнения должно сохраняться в настройках ноды.

### 4.5. Информация о размере результата

Рядом с рамкой, предпочтительно в верхней части рамки или в компактной информационной плашке над ней, отображать рассчитанный итоговый размер.

Пример:

`1536 × 1024 px`

Дополнительно желательно показывать:

`2.0 MP`

Размеры должны обновляться в реальном времени при:
- изменении рамки;
- изменении пропорций;
- изменении мегапикселей;
- изменении кратности;
- изменении входного изображения.

Информация должна оставаться читаемой, даже если рамка находится у края превью или частично выходит за него. Если внутри рамки недостаточно места, плашку следует перемещать в ближайшую свободную область.

## 5. Управление пропорциями

Добавить выпадающий список `Пропорции`.

Варианты:
- Свободные
- 1:1
- 2:3
- 3:2
- 4:3
- 3:4
- 16:9
- 9:16
- 21:9

При выборе фиксированного соотношения ширины и высоты рамка должна изменяться с соблюдением выбранного отношения.

Пример: для 16:9 отношение ширины рамки к высоте всегда равно 16/9.

Добавить переключатель:

- `Фиксация пропорций` — Вкл./Выкл., по умолчанию Вкл.

Поведение:
- При включённой фиксации рамка сохраняет выбранное соотношение сторон при изменении размера за углы.
- При изменении размера за стороны также сохраняется соотношение сторон: вторая размерность корректируется автоматически.
- При выключенной фиксации рамка может изменять пропорции свободно.
- Если выбран режим «Свободные», пользователь может произвольно менять ширину и высоту независимо от положения переключателя.
- Переключатель должен работать без сброса текущего положения рамки.

При выборе другого соотношения сторон рекомендуется сохранять центр и площадь текущей рамки, корректируя размеры под новое соотношение. Если сохранить площадь невозможно из-за ограничений интерфейса, приоритетом является сохранение центра и максимально близкого текущего размера.

## 6. Кнопки управления рамкой

Добавить две кнопки.

### 6.1. «Вписать по всему изображению»

При нажатии рамка устанавливается по границам исходного изображения.

- Левая граница рамки совпадает с левым краем изображения.
- Правая граница — с правым краем.
- Верхняя граница — с верхним краем.
- Нижняя граница — с нижним краем.

Если выбрано фиксированное соотношение, не совпадающее с пропорциями исходника, рамка должна максимально заполнять исходное изображение по площади, сохраняя выбранное соотношение сторон и располагаясь по центру.

### 6.2. «Вписать по центру изображения»

При нажатии рамка устанавливается по центру исходного изображения.

- Центр рамки совпадает с центром изображения.
- Если выбраны фиксированные пропорции, рамка максимально вписывается в исходное изображение по этим пропорциям.
- Если выбраны свободные пропорции, рамка устанавливается по границам изображения.

Обе кнопки должны работать при любом масштабе превью и корректно учитывать текущий размер исходника.

## 7. Настройки итогового разрешения

### 7.1. Кратность

Добавить параметр `Кратность` — целое число, изменяемое пользователем.

По умолчанию: 8.

Предусмотреть удобный диапазон значений, например от 1 до 256, с возможностью ручного ввода.

Принцип работы:
- Итоговая ширина и высота должны быть кратны выбранному значению.
- Например, при кратности 8 обе размерности должны делиться на 8 без остатка.
- При изменении кратности необходимо пересчитывать итоговое разрешение.
- Рамка кадрирования при этом не должна неожиданно перемещаться или менять своё геометрическое положение.

Параметр должен работать по принципу штатной ноды «Выбор разрешения», но не должен зависеть от неё как от обязательной внешней ноды.

### 7.2. Мегапиксели

Добавить параметр `Мегапиксели` с возможностью изменения пользователем.

Рекомендуемые настройки:
- диапазон: 0.1–64 MP;
- шаг: 0.1 MP;
- значение по умолчанию: 2.0 MP.

Предусмотреть ручной ввод числа.

Параметр определяет целевое количество пикселей в выходном изображении, а не размер области исходного изображения, выделенной рамкой.

Формула:

`Количество мегапикселей = ширина × высота / 1 000 000`

При заданном соотношении сторон сначала рассчитывается целевая площадь изображения, затем ширина и высота.

Для соотношения сторон R = W/H:

`W = sqrt(MP × 1 000 000 × R)`

`H = W / R`

После этого обе размерности округляются до допустимых значений с учётом кратности.

Требования:
- Сохранять выбранное соотношение сторон максимально точно.
- Ширина и высота должны быть кратны выбранному значению.
- После округления фактическое количество мегапикселей может немного отличаться от заданного.
- Отображать именно фактическое итоговое разрешение и фактические мегапиксели.
- При изменении мегапикселей не менять положение и пропорции рамки в превью.
- При необходимости выбирать ближайшую допустимую пару размеров, не превышая заданный бюджет мегапикселей, если это не приводит к чрезмерному отклонению от целевого разрешения.

Для режима свободных пропорций использовать текущее соотношение сторон рамки.

### 7.3. Приоритеты параметров

Во избежание конфликтов параметров установить следующий порядок:

1. Геометрия рамки определяет кадр и его соотношение сторон.
2. Выбранное соотношение сторон ограничивает геометрию рамки, если включена фиксация.
3. Мегапиксели задают целевую площадь выходного изображения.
4. Кратность задаёт допустимые значения ширины и высоты.
5. Окончательные размеры вычисляются совместно, с минимальным отклонением от целевого количества мегапикселей.

Визуальный размер рамки в превью и разрешение выходного изображения — разные понятия. Увеличение мегапикселей не должно расширять рамку в координатах исходника.

## 8. Метод масштабирования

Добавить выпадающий список `Метод масштабирования`.

Минимально необходимые варианты:
- Nearest-exact
- Bilinear
- Bicubic
- Lanczos, если доступен в используемом backend.

По умолчанию: Lanczos, если выбранный backend поддерживает этот метод корректно; в противном случае — Bicubic.

Метод используется для масштабирования содержимого кадра до рассчитанного выходного разрешения.

Правила:
- При увеличении разрешения выполнять апскейл выбранным методом.
- При уменьшении разрешения выполнять даунскейл выбранным методом.
- Не менять цвета, экспозицию, контраст, насыщенность или баланс белого намеренно.
- Не применять дополнительную резкость, цветокоррекцию или генеративную обработку.
- Не использовать генеративное заполнение полей внутри этой ноды.

Если исходный кадр не требует масштабирования, не выполнять ненужный дополнительный ресайз.

## 9. Заливка областей outpainting

Добавить параметр `Заливка вне исходного изображения`.

Варианты:
- Прозрачная
- Чёрная
- Белая
- Серая

По умолчанию: Серая.

Правила:
- Если рамка полностью находится внутри исходника, заливка не используется.
- Если рамка частично выходит за исходник, заливка применяется только к новым областям за исходными границами.
- Если рамка полностью находится за пределами исходника, итоговое изображение заполняется выбранным цветом.
- Существующие пиксели исходного изображения сохраняют своё содержимое, за исключением необходимого масштабирования.
- Не изменять содержимое исходника ради заполнения внешних областей.

Для серой заливки использовать нейтральный серый цвет RGB (128, 128, 128).

Для прозрачной заливки использовать альфа-канал со значением 0 в новых областях, а для исходного изображения сохранять исходную альфу, если она присутствует.

**Важно:** стандартный IMAGE ComfyUI обычно передаёт RGB или RGBA в зависимости от ноды и реализации. Проверить, как текущая версия ComfyUI передаёт альфа-канал между нодами. Если формат IMAGE не позволяет сохранить прозрачность в выбранном пути обработки, предусмотреть корректное RGBA-представление, не подменяя прозрачность чёрным цветом без предупреждения. Документировать ограничение, если оно существует.

Для чёрной, белой и серой заливки использовать непрозрачные пиксели.

## 10. Алгоритм обработки изображения

Обработка должна выполняться следующим образом:

1. Получить исходное изображение.
2. Получить сохранённые параметры рамки.
3. Перевести координаты рамки в координаты исходного изображения.
4. Определить итоговую прямоугольную область кадрирования, включая части за пределами исходника.
5. Рассчитать конечные ширину и высоту с учётом пропорций, мегапикселей и кратности.
6. Создать целевой холст нужного размера с выбранной заливкой.
7. Определить пересечение рамки с исходным изображением.
8. Вырезать доступную область исходника.
9. Масштабировать содержимое до размера, соответствующего его доле в итоговом кадре, используя выбранный метод.
10. Разместить масштабированное содержимое на холсте в правильном положении.
11. Сохранить заданную заливку во всех областях, не покрытых исходным изображением.
12. Вернуть итоговое изображение, ширину и высоту.

Координаты должны рассчитываться с учётом того, что рамка может выходить за все четыре границы изображения.

При этом нельзя сначала обрезать рамку границами исходника и терять информацию о выходе за них. Иначе функция outpainting не будет работать.

При необходимости использовать вещественные координаты рамки и аккуратное округление при преобразовании в пиксельные координаты, чтобы минимизировать ошибки смещения на границах.

## 11. Выходы ноды

Обязательные выходы:

1. `изображение` — IMAGE.
2. `ширина` — INT.
3. `высота` — INT.

`ширина` и `высота` должны соответствовать фактическим размерам выходного изображения после всех преобразований.

Эти значения должны быть пригодны для подключения к другим нодам ComfyUI, принимающим INT.

Выходы должны корректно работать при повторном выполнении workflow и при изменении входного изображения.

## 12. Дополнительные функции, которые необходимо предусмотреть

### 12.1. Сохранение состояния рамки

Положение рамки, её размеры, выбранные пропорции и параметры разрешения должны сохраняться в состоянии workflow.

После сохранения и повторного открытия workflow рамка должна восстанавливаться в том же положении относительно изображения.

Для этого желательно хранить координаты рамки в нормализованной системе относительно исходного изображения либо в другой устойчивой системе координат, которая корректно учитывает выход за границы.

Не хранить положение рамки исключительно в экранных координатах.

### 12.2. Сброс и повторное применение

При замене входного изображения на другое:
- корректно определить его новые размеры;
- сохранить настройки пропорций, кратности и мегапикселей;
- по возможности сохранить относительное положение и размеры рамки;
- не допускать появления некорректной или невидимой рамки.

Предусмотреть кнопку `Сбросить рамку`, которая устанавливает рамку по всему изображению с учётом выбранных пропорций.

### 12.3. Защита от ошибочных значений

Не допускать:
- нулевой ширины или высоты;
- отрицательного разрешения;
- бесконечных координат;
- недопустимого значения мегапикселей;
- зависания интерфейса при очень больших изображениях;
- создания холста с неограниченными размерами.

Установить разумные ограничения на итоговое разрешение и выдавать понятную ошибку при превышении лимита памяти.

### 12.4. Работа без изображения

Если вход не подключён или изображение ещё не получено, показывать пустое превью с понятным сообщением о необходимости подключить изображение.

Не допускать ошибок JavaScript и Python только из-за отсутствия входного изображения.

### 12.5. Удобство взаимодействия

Предусмотреть:
- курсор перемещения при наведении на внутреннюю область рамки;
- курсоры изменения размера на углах и сторонах;
- корректную обработку отпускания кнопки мыши за пределами превью;
- отсутствие случайного перемещения рамки при обычном клике;
- обновление информации о разрешении без заметных задержек;
- возможность продолжать работать с нодой после изменения масштаба и размеров интерфейса.

Не допускать, чтобы рамка исчезала под другими элементами интерфейса или становилась недоступной для захвата.

## 13. Производительность

Превью не должно постоянно выполнять полный пересчёт изображения во время каждого движения мыши.

Рекомендуется:
- выполнять геометрические изменения рамки на frontend;
- пересчитывать координаты и отображаемый размер без обработки полного выходного изображения;
- выполнять окончательное кадрирование на backend при запуске ноды;
- использовать кэширование только там, где оно не нарушает корректность при изменении параметров.

Операции над исходным изображением не должны изменять оригинальный тензор, используемый другими нодами.

## 14. Структура проекта и поставка

Разместить реализацию в отдельной папке:

`ComfyUI/custom_nodes/DeggCropImage/`

Предусмотреть:
- Python-файл с регистрацией ноды и обработкой изображения;
- `__init__.py`;
- frontend-файлы, если они необходимы;
- `README.md` с установкой, требованиями, описанием параметров и известными ограничениями.

Не добавлять ненужные зависимости и не изменять файлы других кастомных нод.

Агент должен предоставить полный исходный код всех файлов, необходимых для работы, а не только фрагменты или псевдокод.

## 15. Критерии приёмки

Нода считается готовой только после проверки следующих сценариев:

1. При подключении изображения превью появляется автоматически.
2. Рамка перемещается мышью без изменения размера.
3. Все четыре угла и четыре стороны корректно изменяют размер рамки.
4. Фиксация пропорций соблюдается при изменении размера.
5. При выключенной фиксации рамка свободно меняет пропорции.
6. Все перечисленные пропорции работают корректно.
7. Рамка может выходить за любую границу исходника.
8. При выходе рамки за границы превью автоматически уменьшается настолько, чтобы показать рамку целиком.
9. Затемнение изменяется в пределах от 0 до 100% и влияет только на превью.
10. Кнопка «Вписать по всему изображению» работает корректно.
11. Кнопка «Вписать по центру изображения» работает корректно.
12. Мегапиксели и кратность корректно влияют на итоговые размеры.
13. Отображаемое разрешение совпадает с фактическими размерами выходного изображения.
14. Каждый метод масштабирования доступен и работает, если он заявлен в интерфейсе.
15. Все варианты заливки работают при выходе рамки за исходные границы.
16. При прозрачной заливке сохраняется корректная альфа-прозрачность новых областей.
17. Выходы IMAGE, INT и INT имеют правильные типы и значения.
18. Настройки рамки сохраняются после сохранения и повторного открытия workflow.
19. Нода корректно работает с обычным изображением и батчем изображений.
20. Нет ошибок frontend, Python и повреждения данных исходного изображения.
21. Нода работает в заявленной версии ComfyUI Nodes 2.0 или выше.

## 16. Порядок разработки

Разрабатывать последовательно:

Этап 1. Изучить актуальные API ComfyUI Nodes 2.0, штатные ноды-примеры и структуру frontend-расширений.

Этап 2. Создать минимальную ноду с входом IMAGE и интерактивным превью.

Этап 3. Реализовать рамку, перемещение, изменение размера, пропорции и автоматическое масштабирование превью.

Этап 4. Реализовать расчёт разрешения, кратность и мегапиксели.

Этап 5. Реализовать кадрирование, масштабирование, outpainting и варианты заливки.

Этап 6. Реализовать выходы IMAGE, INT и INT.

Этап 7. Проверить сохранение состояния, работу в workflow, батчи, ошибки и производительность.

Этап 8. Предоставить готовую папку ноды и отчёт о пройденных тестах.

Не считать этап завершённым только потому, что интерфейс отображается. Каждую функциональность необходимо проверить фактически в ComfyUI.

## 17. Итоговое требование

Создать полноценную рабочую кастомную ноду **Degg Crop Image**, визуально и функционально напоминающую инструмент кадрирования Capture One.

Главное требование — естественное управление кадром непосредственно на изображении мышью, в том числе возможность расширять рамку за пределы исходника для outpainting.

Не заменять рамку набором числовых полей. Числовые параметры разрешения и дополнительные настройки должны дополнять интерактивное кадрирование, а не заменять его.

Перед завершением разработки проверить реальную совместимость с используемой версией ComfyUI и предоставить готовую реализацию со всеми файлами и инструкцией по установке.
