# Degg Crop Image — спецификация

Нода ComfyUI: кадрирование с интерактивной рамкой на теле ноды; рамка может
выходить за изображение (аутпейнт) без второго входа.

- Класс: `DeggCropImage`, отображаемое имя `Degg Crop Image`
- Категория: `My_custom_nodes/Image`
- Выходы: `IMAGE`, `MASK`, `width`, `height` (фактические размеры результата)

---

## 2. Контракт входов/выходов

| Вход | Тип | По умолчанию | Смысл |
|------|-----|--------------|-------|
| `image` | IMAGE | — | источник (батч `[B,H,W,C]`) |
| `lock_ratio` | BOOLEAN | `true` | удерживать пропорцию при перетаскивании |
| `center_x` | INT ±100000, step 1 | `0` | смещение центра рамки по X от центра изображения, px |
| `center_y` | INT ±100000, step 1 | `0` | смещение центра рамки по Y от центра изображения, px |
| `frame_w` | INT 0…100000, step 1 | `0` | ИТОГОВАЯ ширина результата, px |
| `frame_h` | INT 0…100000, step 1 | `0` | ИТОГОВАЯ высота результата, px |
| `output_size` | STRING (скрыт) | `` | ручной размер результата `Ш,В`; пусто = считать по мегапикселям |
| `aspect_ratio` | COMBO | `free` | протокол: `free,1:1,2:3,3:2,4:3,3:4,16:9,9:16,21:9` |
| `megapixels` | FLOAT 0.1…64 | `2.0` | целевая площадь, 1 MP = 1024² |
| `multiplicity` | INT 8…128, step 4 | `8` | кратность сторон результата |
| `resample` | COMBO | `lanczos` | `lanczos,bicubic,bilinear,nearest-exact` (без перевода) |
| `fill` | COMBO | `transparent` | `transparent,black,white,gray` — фон вне источника |
| `dim_outside` | INT 0…100 | `50` | затемнение вне рамки, только отображение |
| `mask` | MASK (опц.) | — | заменяет альфу источника (1 = непрозрачно) |
| `crop_rect` | STRING (скрыт) | полный кадр | `{x, y, w, h}` в долях изображения |

Порядок строк таблицы = порядок виджетов на теле ноды (после превью): `lock_ratio`,
`center_x`, `center_y`, `frame_w`, `frame_h`, `aspect_ratio`, `megapixels`,
`multiplicity`, `resample`, `fill`, `dim_outside`. `image`/`mask` — сокеты,
`crop_rect` и `output_size` скрыты.

`center_x`/`center_y`/`frame_w`/`frame_h` — UI-поля (как `aspect_ratio`/`lock_ratio`):
рамку на сервере считает `crop_rect`, а эти поля её описывают в UI и пишутся
интерфейсом. `output_size` хранит ручной размер результата — без него сервер
считал бы размер только по мегапикселям.

COMBO-значения — протокол: подписи меняются через `getOptionLabel`, значения в
workflow не переводятся.

## 3. Разрешение результата

Повторяет ядро ComfyUI (`comfy_extras/nodes_resolution.py`, «Выбор разрешения»):

```
total = megapixels * 1024 * 1024
scale = sqrt(total / (rw * rh))
width = max(step, round(rw * scale / step) * step)
height = max(step, round(rh * scale / step) * step)
step = max(1, int(multiplicity))
```

- `round` банковский (`py_round`), стороны округляются независимо;
- шаг не клампится внутри функции — диапазон `8…128` задаёт `INPUT_TYPES`
  (старые воркфлоу с меньшим шагом считаются как есть);
- примеры: `16:9 / 2 MP / 8 → 1928×1088`, `1:1 / 2 MP / 8 → 1448×1448`,
  `1:1 / 1 MP / 8 → 1024×1024`, `1:1 / 0.5 MP / 8 → 728×728`;
- плашка в JS показывает фактические `W × H` и фактические MP (1928×1088 = 2.10).

## 4. Геометрия кадра

`frame_geometry(src_w, src_h, rect, out_w, out_h)`:

1. рамка в долях → пиксельные границы источника, дробные границы
   раскрываются наружу (`floor` / `ceil`), чтобы не терять пиксели;
2. коэффициент `out_w / frame_w_px` (по X) и `out_h / frame_h_px` (по Y);
3. для каждой границы считаются координаты вставки в холст результата;
4. отрицательные координаты рамки = аутпейнт: холст предзаполняется цветом
   `fill`, изображение вставляется поверх.

`render_frames(...)` возвращает `(canvas, mask_out, out_w, out_h)`:

- `mask_out` — 1 внутри рамки, 0 в залитой области (для `transparent`);
- batch: общий размер, одинаковые координаты, каждый кадр обрабатывается отдельно;
- пустой вход → `(empty_image, zeros, 0, 0)`.

Заливка — **фон под изображением** (так же в DOM-редакторе: слой `fill` создаётся
раньше `img`) — внутри кадра картинку не перекрывает.

## 5. DOM-редактор (Nodes 2.0)

- `addDOMWidget(..., { hideInPanel: true, hideOnZoom: false })` — панель свойств
  иначе пишет `widget.width` в живой виджет и зажимает контент;
- `computeLayoutSize` возвращает `minHeight`, высота = ширина × соотношение +
  плашка (без `scrollHeight`/`offsetHeight`/`computeSize`);
- превью источника берётся по проводу мгновенно (`p:/o:/i:/n:`), без выполнения
  воркфлоу; смена изображения в upstream-ноде (загрузка в `LoadImage`) приходит
  ДВУМЯ каналами: legacy (`BaseWidget.setValue`, upload-виджет) зовёт
  `source.onWidgetChanged`, Nodes 2.0 (`createWidgetUpdateHandler`) зовёт только
  `widget.callback` и `node.onWidgetChanged` не вызывает. Поэтому обёрнуты оба
  канала: `watchedHandler` на хуке узла и `watchSourceWidgets()` на callback'ах
  виджетов источника (с восстановлением в `detachSource()`);
- смена картинки определяется подменой объекта `app.nodeOutputs[locator]`
  (`sourceOutputsChanged()`), а не ключом/именем файла: перезаливка файла с тем
  же именем не меняет ключ, но `setOutputsByLocatorId` всегда присваивает новый
  объект → принудительный `loadSource({ force: true })` с кэш-бастером;
- зум/пан графа не влияют на координаты: экранные координаты приводятся к
  локальным через `getBoundingClientRect`;
- изменения виджетов (`dim_outside`, `fill`, `megapixels`, `multiplicity`)
  прогоняются через обёртку callback → `layout()`, иначе DOM не перерисуется;
- бар редактора:
  - «Вписать» (`fitFrameFrac`) — равномерный масштаб ТЕКУЩЕЙ рамки
    `s = min(1/w, 1/h)` вверх и вниз до касания ближайших границ + центр;
    пропорции и режим не меняются;
  - «По центру» (`centerFrameFrac`) — только перенос центра рамки в центр
    изображения; размер и пропорции сохраняются, выход за границы разрешён;
  - «Сбросить» — рамка `0,0,1,1` + `aspect_ratio='free'` + `lock_ratio=false`;
    `megapixels`/`multiplicity`/`resample`/`fill`/`dim_outside` НЕ трогаются
    (это настройки результата, а не рамки); `applyAspect` не вызывается;
- «Зафиксировано» (`lock_ratio`) — фиксирует ТЕКУЩИЕ пропорции рамки
  (`state.ratioLock = currentPxRatio()`), а не подставляет пресет из списка:
  при `aspect_ratio='free'` захваченное соотношение (`ratioLock`) имеет приоритет
  над пресетом; `effectiveRatio() = ratio() ?? ratioLock ?? currentPxRatio()`;
  выбор пресета в списке применяет его И включает замок; выбор «Свободные»
  снимает замок (`programmatic(aspectWidget, 'free')`);
  `lock_ratio`/`aspect_ratio` в Python на выход не влияют (выход = `crop_rect`),
  поэтому «Свободно» + захваченное соотношение не нарушает протокол combo;
- ⛔ ПРАВИЛО ВЫБОРА: числовая опция ноды — это НАТИВНЫЙ виджет `INPUT_TYPES`
  (нижние опции, нативный вид, значение ездит в workflow), а НЕ кастомный
  `<input>` внутри DOM-редактора. Кастомный DOM-контрол — только для составных
  значений (несколько полей, свой вид, live-привязка к сцене). Прецедент:
  координаты сначала были кастомным `<input type="number">` — выглядело «не как у
  остальных», не попадало в workflow; переделано в нативные опции;
- координаты — НАТИВНЫЕ опции ноды (`center_x`, `center_y`: INT, шаг 1, диапазон
  со знаком), стоят сразу под виджетом «Фиксация пропорций» и выглядят как
  остальные бегунки ноды (label + `−` + значение + `+`); значения — СМЕЩЕНИЕ
  ЦЕНТРА РАМКИ относительно центра изображения, в ПИКСЕЛЯХ оригинала
  (`frameCenterOffset`/`moveFrameToOffset`);
  - рамка меняется → координаты перезаписываются (`syncCoords`), запись ТИХАЯ
    (`setWidgetValueQuiet`, без callback'а), иначе каждый кадр drag'а
    перезапускал бы ноду;
  - пользователь правит координату → callback виджета → рамка едет
    (`applyCoords` → `moveFrameToOffset`);
  - `center_x`/`center_y` в Python — UI-поля (как `aspect_ratio`/`lock_ratio`):
    рамку считает `crop_rect`;
- РАЗМЕР РЕЗУЛЬТАТА (`frame_w`/`frame_h`) — это ИТОГОВЫЙ размер картинки (те
  же числа, что в плашке и в выходах `width`/`height`), а не размер обреза.
  Два режима, переключаются сами:
  - **по мегапикселям** (обычный): результат = пропорции рамки + MP + кратность,
    поля просто показывают итог;
  - **ручной**: результат = введённое число, округлённое до кратности
    (1333 × 750 при кратности 8 → 1336 × 752);
  - в ручном режиме остальные параметры ПОДСТРАИВАЮТСЯ под введённый размер:
    пропорции рамки приводятся к пропорциям результата (площадь и центр
    сохраняются — как при выборе пресета, иначе кадр растянулся бы), а
    мегапиксели показывают эквивалент результата (`Ш × В / 1024²`);
  - **обратное направление**: выбор пресета пропорций или правка мегапикселей
    сбрасывают ручной режим, и поля снова показывают размер, посчитанный от MP
    (16:9 + 2 МП → 1928 × 1088);
  - ручной размер хранится в скрытом `output_size` (`Ш,В`), поэтому переживает
    перезагрузку воркфлоу и не зависит от точности поля «Мегапиксели» (шаг 0.1);
  - ⛔ ИТОГОВЫЙ РАЗМЕР СЧИТАЕТСЯ ПО ПИКСЕЛЯМ КАДРА (`pxRect()`), а не по его долям:
  пропорции результата = `rect.w*src_w : rect.h*src_h` — ровно как в Python
  (`output_size(rect["w"] * src_w, rect["h"] * src_h, ...)`). Для НЕКВАДРАТНОГО
  источника доли и пиксели дают разные пропорции: рамка 1731×974 px (16:9) в
  долях выглядит как 0.636×0.634 (почти квадрат) → по долям получалось
  1448×1448 вместо 1928×1088, и UI врал о размере результата;
- ⛔ ИНВАРИАНТ: пропорции кадра и пропорции ручного результата всегда совпадают.
    Разошлись (например, ручной размер остался от прошлого воркфлоу, а выбраны
    16:9 и 2 МП) — ручной режим сбрасывается, иначе MP и пресет молча
    игнорировались бы, а кадр растягивался бы. Сверка (`reconcileManual`)
    выполняется ДО отрисовки плашки, иначе плашка показывала бы старый размер,
    а поля — новый;
  - свободный drag (меняет пропорции кадра) подстраивает ручной размер без
    рывков: ширина сохраняется, высота следует за пропорциями;
- Shift-модификаторы (в режиме «Свободно»):
  - Shift + перетаскивание ВНУТРИ рамки — движение строго по доминирующей оси
    (`axisDelta`: `|dx| >= |dy|` → горизонталь);
  - Shift + тянутая сторона/угол — ресайз с сохранением текущих пропорций
    (`state.drag.ratio`, снятый на `pointerdown`); замок при этом НЕ включается;
- иконка «?» (`.degg-crop__help`) — в ПРАВОМ ВЕРХНЕМ УГЛУ ПРЕВЬЮ (внутри
  `.degg-crop__stage`, как в `Degg_Images_Save_Compare`); всплывающая подсказка
  (`.degg-crop__helpbox`) — в корне (сцена режет содержимое, `overflow:hidden`),
  позиционируется под кнопкой через `syncHelpAnchor()`;
  открывается по клику/наведению, текст — `LABELS.help` (RU/EN), включает
  описание Shift-приёмов и координат;
- DRAG-ИНВАРИАНТ: масштаб и смещение сцены фиксируются на `pointerdown`
  (`state.drag.view`) и используются во всех `pointermove`. Иначе рост рамки
  расширяет union → меняет `scale` → следующий `pointermove` считает дельту по
  новому масштабу, и рамка разгоняется до клампа (доля сцены → 88);
- `state.suppress` защищает от реентерабельности: программная запись виджета
  (`programmatic`) не должна вызывать callback'и, которые сами пишут в виджеты;
- язык: `Comfy.Locale` (через `app.extensionManager.setting.get`) → `ru` при
  префиксе `ru`, иначе `en`; словари в `LABELS`; подписи кнопок, combo
  (`getOptionLabel`) и замка (`options.on/off`) переприменяются на событии
  legacy-настроек `Comfy.Locale.change` — без перезапуска ComfyUI;
- состояние: `node.__deggCrop = { widget, layout, state, refresh, setFrac,
  centerX, centerY, helpBox, helpBtn, syncCoords }` — экспорт для живых проб;
- `onConfigure`/`loadedGraphNode` → `refresh()`; сериализация рамки в `crop_rect`.

## 6. Инварианты

- никаких `setInterval` / `MutationObserver` / глобальных слушателей / canvas-рисования;
- только `window.comfyAPI` (не `scripts/app.js`), `registerExtension` +
  `beforeRegisterNodeDef`;
- `fill` не перекрывает изображение внутри кадра;
- `resample` и `aspect_ratio` — протокольные значения, переводятся только подписи;
- `IS_CHANGED` не нужен: все влияющие входы — обычные виджеты/входы.

Живая DOM-проба (`_probe_live_dom_crop_image.py`, `ok: 84`) покрывает новую

поля координат (показывают смещение центра, ввод двигает рамку), Shift-ресайз
(пропорции сохранены, замок не включён), Shift-перемещение (одна ось), иконка «?»
(открывается/закрывается, текст непустой, кнопка стоит в правом верхнем углу
ПРЕВЬЮ — внутри `.degg-crop__stage`), отсутствие разгона рамки за пределами
изображения. Пропорции в пробе считаются по `frac` (дробные координаты), а не по
`frameBox`: при сжатой сцене `frameBox` округляется до целых CSS-пикселей.

Ручной размер результата проверяется в смоуке (чистая математика `snapSize` /
`outputSizeFor` / `frameWithRatio`: округление до кратности, приоритет ручного
размера над MP, «16:9 + 2 МП → 1928 × 1088», пропорции рамки следуют за
результатом с сохранением площади и центра) и в живой пробе (1000 × 1000 →
плашка «1000 × 1000 px», поля = 1000, мегапиксели = эквивалент, пропорции кадра
1:1, ручной размер сохранён в `output_size`; 1333 → 1336 с кратностью 8; правка
мегапикселей возвращает режим MP; 16:9 + 2 МП → поля 1928 × 1088; выбор пресета
при активном ручном размере сбрасывает его; устаревший ручной размер из
прошлого воркфлоу не перебивает пресет и мегапиксели).

⚠️ Проба обязана покрывать НЕКВАДРАТНЫЙ источник: на `example.png` (768×768)
доли и пиксели совпадают, и ошибка «размер по долям» невидима. Отдельный
регресс подставляет источник 2720×1536 (картинка из воркфлоу «Test Crop») и
рамку долями 0.636×0.634 → в пикселях 16:9 → ожидается 1928 × 1088. Без
исправления тест даёт ровно картину пользователя (1448 × 1448).

`tests/_check_real_workflow.py` — та же проверка на РЕАЛЬНОМ воркфлоу: реальная
картинка `image_flux3_klein_distilled_t2i_00023_.png` (2720×1536) и сохранённый
`crop_rect` → плашка и поля = 1928 × 1088.

Мутации детекторов этой семантики (проверено, файлы восстановлены): плашка без
ручного размера, непропорциональный кадр, правка MP без сброса ручного режима,
поля без итогового размера — каждая даёт красный детектор (статический аудит или
живая проба).

Кнопки проверяются на трёх уровнях: `_smoke_crop_image.mjs` — чистая математика
`centerFrameFrac`/`fitFrameFrac` (размер сохраняется; масштаб равномерный вверх и
вниз; центр совпадает), `_probe_live_dom_crop_image.py` — реальные клики по кнопкам
(рамка, `crop_rect`, `aspect_ratio`, `lock_ratio`, геометрия на сцене) и смена языка
на лету через `dispatchChange('Comfy.Locale', …)`, `_audit_crop_image.mjs` — связка
«кнопка → функция» и отсутствие старого «Вписать всё». Детекторы проверены
мутациями: `Math.min → Math.max` даёт 5 FAIL в смоуке, удаление
`setWidgetValue(lockWidget, false)` — FAIL в аудите.

Мутации новых детекторов (проверено, файл восстановлен):
- `state.ratioLock = 1` (вместо захвата текущих пропорций) → живая проба:
  FAIL «Зафиксировано» держит захваченные пропорции при ресайзе»;
- `axisDelta` без оси → FAIL «Shift при перемещении держит одну ось»;
- `state.drag.ratio → null` → FAIL «Shift + край в «Свободно» сохраняет пропорции»;
- `sourceFromLocal(localFromEvent(event))` (без зафиксированного `drag.view`) →
  FAIL «drag за пределы изображения не разгоняет рамку» (доля кадра 88) и
  FAIL по плашке; в аудите при этом краснеют оба статических детектора
  «масштаб сцены фиксируется на pointerdown» / «pointermove считает точку по
  зафиксированному view».

Мутации детекторов нативных координат и кнопки «?» (проверено, файлы
восстановлены):

| мутация | что краснеет |
|---------|--------------|
| «?» переехал из `stage` в `root` | аудит: «кнопка «?» живёт в превью»; живая проба: «кнопка «?» стоит в правом верхнем углу превью» |
| координаты пишутся через `setWidgetValue` (с callback'ом) | аудит: «запись координат БЕЗ callback'а (тихая)» |
| callback'и координат не зовут `applyCoords` | аудит: «правка координат двигает рамку»; живая проба: «ввод координат ставит центр рамки в заданную точку» |

Про первые два мутационных прогона: детектор «тихая запись» сначала смотрел на
любое упоминание `setWidgetValueQuiet(centerXWidget` и потому не краснел на
мутации (осталась ветка «изображения нет»); после правки детектор требует
конкретную форму `setWidgetValueQuiet(centerXWidget, Math.round(offset.x))`.
